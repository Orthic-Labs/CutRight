# Real-Footage Benchmark + Acceptance

**Spec for the implementation agent.** Written 2026-07-31 against the `a8d4584` tree + REV2.
Design authority: the Video Editor skill; **Adrian's visual acceptance is the ship gate.** Fixtures are
private; this spec defines their *structure*, not their content. No footage, filenames, or numbers here
are fabricated — thresholds are labelled starting candidates, and reported results must be measured.

## 0. The contract (lead)

A feature is **not** done because it produced an MP4. It is done when, on a fixed private fixture suite,
it passes the per-stage machine metrics **and Adrian accepts the visual result** (vision plan §21). The
suite is fixed (so results are comparable run-to-run), private (never committed, never uploaded), and
built to stress each pipeline stage. Machine metrics are *necessary, not sufficient*; the human gate is
final, and model-assisted QA is advisory only.

## 1. The fixture suite

Canonical set (vision §21), grouped by what each stresses. IDs are labels, not content claims.

| ID | Type | Count | Raw length | Stresses |
|---|---|---:|---|---|
| `TH-1..3` | YouTube talking-head | 3 | 10–25 min | core editorial brain, natural pacing, captions, colour |
| `MT-1..2` | Multi-take, many false starts | 2 | 15–30 min | best-take selection, false-start/filler triage, dedup |
| `VR-1..3` | Direct vertical recordings | 3 | 1–5 min | 9:16 native, reframe off-path, vertical captions |
| `LG-1..2` | Long recording → 4 shorts each | 2 | 30–60 min | shorts extraction, diversity, standalone completeness |
| `HDR-1` | iPhone HDR source | 1 | 5–15 min | HDR→SDR tone-map, colour pipeline, metadata handling |
| `NOISE-1` | Noisy room | 1 | 10–20 min | denoise decision, VAD in noise, audio finish, loudness |
| `MIXFPS-1` | Mixed frame-rate / mixed sources | 1 | 10–20 min | working/output timebase, VFR, rotation, normalisation |

Total: 13 fixtures. The brief's example (3× talking-head, 2× multi-take, 1× HDR, 1× noisy, 1× mixed-FPS)
is the minimum core; the full suite above is the production-readiness bar.

## 2. Fixture layout (private, gitignored)

```text
fixtures/                         # NEVER committed, NEVER uploaded; listed in .gitignore
├── suite.json                    # manifest: [{id, type, sources[], duration_ms, fps, hdr, notes}]
├── TH-1/
│   ├── sources/                  # raw footage (or absolute-path references to private media)
│   ├── meta.yaml                 # type, duration_ms, fps (rational), hdr, rotation, notes
│   └── expected/                 # ground-truth annotations (human-authored, private)
│       ├── transcript-ref.json   # reference word transcript (for WER / boundary comparison)
│       ├── beats.json            # intended beat boundaries + labels
│       ├── takes.json            # which candidates are duplicate takes of the same beat
│       ├── keepcut.json          # intended keep/cut decisions (the "right" edit)
│       └── reframe-ref.json      # acceptable subject centres per segment (for vertical fixtures)
├── MT-1/ ...
└── ...
```

- `expected/` is the ground truth the metrics are measured against; it is authored by Adrian (or from his
  accepted edits), not generated by the engine under test.
- `suite.json` pins each fixture's source BLAKE3 hashes so a fixture cannot silently change between runs.
- Fixtures live outside any `.video-project/`; the skill ingests them by reference and never modifies
  them.

## 3. Per-stage metrics + pass criteria

Thresholds are **starting candidates**, calibrated from Adrian's first accepted runs. "Measured how" is
the artifact the metric is read from.

| Stage | Metric | Measured from | Pass (starting candidate) |
|---|---|---|---|
| Ingest | source hash stability; metadata completeness | `sources/manifest.json` | 100% sources registered, hashes stable on rerun |
| Transcribe/benchmark | word error rate vs `transcript-ref.json`; benchmark `decision` | `analysis/transcripts/*.json`, bench report | WER ≤ 5%; `decision` resolved (HeardRight primary) |
| Take selection | **editor acceptance of selected takes** | `feedback/decisions.jsonl` vs `takes.json` | ≥ 85% of brain picks accepted |
| Beat/red-thread | beat-boundary agreement vs `beats.json` | `edit/editorial-plan.json` | ≥ 80% boundary agreement |
| Boundary/cut | **boundary correction rate**; **clipped/ghost word count** | decisions (segment flags), second-ASR vs output transcript | correction ≤ 15%; clipped/ghost words = 0 |
| Rough-cut render | **rough-cut time**; A/V drift | job timing, probe | within target on the Mac; drift within tolerance |
| Captions | **caption timing errors**; reading speed; **caption/subject collisions** | `edit/captions-*.srt` vs output transcript, spatial check | timing error ≤ 80 ms; 0 collisions; speed in range |
| Reframe | subject framed; **manual placement fixes**; anchor jitter | `analysis/reframe-plan.json` vs `reframe-ref.json` | ≥ 90% anchors accepted; jitter within tolerance |
| Finish/motion | **graphic acceptance rate**; **manual placement fixes** | decisions vs `finish/finish-plan.json` | graphic acceptance ≥ 85%; few manual fixes |
| Audio | loudness target; true peak; cut pops; noise-floor | audio metering | within target LUFS + true-peak ceiling; 0 pops |
| Final render | **final-render time**; dimensions; **final length** fit | probe vs `brief/platform-brief.json` | dimensions exact; length within platform target |
| QA | machine-gate pass; **crash/recovery** | `qa/report.json`, run log | all gates pass; a killed run resumes to a reviewable state |
| Efficiency | **provider cost**; **cache hit rate** | provider envelopes, job cache | cost ≤ budget (0 offline); cache hit high on rerun |

## 4. The human-acceptance gate (final)

Machine metrics qualify a fixture; **Adrian accepting the visual result passes it.** This gate:

- is per fixture and per deliverable (the YouTube final and each vertical final are judged separately);
- cannot be satisfied by an agent or a model — model-assisted QA (Gemini/Twelve) findings are advisory;
- is recorded as a content-bound acceptance record (a `final` verdict in `feedback/decisions.jsonl`,
  bound to the exact final's BLAKE3 per REV2 §5.4) plus a benchmark acceptance line in
  `fixtures/<id>/expected/acceptance.json` (`{fixture, deliverable, accepted, accepted_at, notes}`).
- A fixture with all machine metrics green but no human acceptance is **not passed**.

## 5. Suite-level pass + regression

- **Fixture pass:** every §3 stage threshold met **and** human acceptance recorded for each deliverable.
- **Suite pass:** all 13 fixtures pass, and the aggregate rates (take acceptance, boundary correction,
  caption timing, graphic acceptance) sit above their floors across the suite.
- **Regression rule:** a change that drops any accepted fixture's metric below its floor, or that would
  flip a recorded human acceptance, is a regression and blocks the change. Rerun the affected fixtures
  after any edit to the editorial brain, boundary logic, caption profile, reframe, or finish pipeline.

## 6. Running the benchmark (procedure)

For each fixture, run the skill end-to-end in `reviewed` mode and record results:

1. `videoctl project init` + `ingest` the fixture sources (hash-pinned).
2. Run [transcribe](../skills/content-video-editor/workflows/transcribe.md) →
   [rough-cut](../skills/content-video-editor/workflows/rough-cut.md) →
   [review](../skills/content-video-editor/workflows/review.md) →
   [finish](../skills/content-video-editor/workflows/finish.md) →
   [reframe](../skills/content-video-editor/workflows/reframe.md) →
   [qa](../skills/content-video-editor/workflows/qa.md) →
   [export](../skills/content-video-editor/workflows/export.md) (and [shorts](../skills/content-video-editor/workflows/shorts.md)
   for `LG-*`).
3. Diff engine outputs against `expected/` to compute the §3 metrics; capture timing + cost from job
   receipts.
4. Present each deliverable for Adrian's visual acceptance; record it (§4).
5. Write the per-fixture result + the run digest ([AUTONOMY-LADDER.md](AUTONOMY-LADDER.md) §6).

The benchmark is run/observed by a human; it is not an automated fabrication that declares its own pass.

## 7. Privacy + integrity

- Fixtures are **private**: gitignored, never committed, never uploaded. Cloud analysis stays off during
  benchmark runs unless Adrian explicitly consents per fixture (and even then, proxy-only + budgeted).
- Source hashes are pinned in `suite.json`; a fixture whose hash changes is re-validated before its
  results count.
- **No fabricated footage, filenames, quotes, or statistics.** Report only measured numbers; an
  unmeasured metric is reported as "not measured," not estimated.

## Engine gaps to know

- **Most §3 metrics are not auto-collected yet.** `qa` today checks only container/stream/dimension +
  benchmark + captions/evidence presence (REV2 §13.2); take-acceptance, boundary-correction, caption
  timing, collision, graphic-acceptance, loudness, timing, and crash/recovery metrics require the
  per-deliverable QA matrix + receipts + the decision ledger to be built (REV2 P0-A/P0-B, P1 §10/§13).
  Until then, compute these metrics by diffing engine outputs against `expected/` manually and say so.
- The `expected/` ground-truth annotations and `fixtures/suite.json` manifest are an addition to the
  repo; they must be authored from Adrian's real footage and accepted edits — **do not generate them
  from the engine under test**, or the benchmark grades itself.
- WER/boundary comparison needs the second-ASR verifier path (WhisperX) and the corrected
  HeardRight-primary benchmark policy (REV2 P1 §8); the current inverted policy can report `unresolved`
  for two good providers, which would wrongly fail the transcribe stage.
- Crash/recovery (§3 QA row) depends on pipeline-wide content-addressed resumability (REV2 §10.5), which
  is partial; test it, and report fixtures whose recovery required a manual re-run.
