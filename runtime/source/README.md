# Corresponding-Source Archive Layout

Created by CR-V2-B1-022. This file scaffolds the corresponding-source
archive contract; **no archive bytes exist yet** — archives are generated
when a binary actually enters a signed runtime pack.

## 1. Layout

```
runtime-source/<component>/<version>/<target>.tar.zst
runtime-source/<component>/<version>/<target>.manifest.json
```

Example (FFmpeg n8.1, LGPL-2.1-or-later):

```
runtime-source/ffmpeg/n8.1/aarch64-apple-darwin.tar.zst
runtime-source/ffmpeg/n8.1/aarch64-apple-darwin.manifest.json
```

`<component>` is the corpus `source_id` (e.g. `ffmpeg`), `<version>` the
pinned upstream version, `<target>` the platform triple of the shipped
binary. One archive per (component, version, target) shipped binary.

## 2. Manifest contract

Every binary-runtime row MUST carry all five contract fields; a row missing
any of them fails `scripts/legal/build-corresponding-source.py`:

| Field | Meaning |
| --- | --- |
| `source_revision` | Immutable revision the source snapshot was pinned at (corpus row revision). |
| `patches` | Local patch files applied before the build (list; may be empty; each must exist). |
| `configure_args` | Exact build configuration used for the shipped binary (e.g. the FFmpeg `./configure` line; no `--enable-gpl`, no `--enable-nonfree` for FFmpeg). |
| `source_sha256` | SHA-256 of the generated corresponding-source archive. |
| `binary_sha256` | SHA-256 of the shipped binary the archive corresponds to. |

Rows additionally carry `component`, `version`, `target`, `source_root`, and
`notice_path` (path to the governing THIRD_PARTY.yml) — all required.

## 3. Generation rules

Archives are produced by `scripts/legal/build-corresponding-source.py`
(stdlib-only, deterministic, offline):

- Inputs are PINNED LOCAL source snapshots under `runtime/source/<component>/`;
  the script never fetches from the network.
- Determinism: tar entries are sorted, mtime/uid/gid are fixed, USTAR
  format, and compression (when available) is single-threaded at a fixed
  level. Two builds from the same snapshot are byte-identical; `--self-test`
  proves it.
- Compression: stdlib `compression.zstd` (Python ≥ 3.14) yields `.tar.zst`.
  If zstd is unavailable offline, the documented deterministic fallback is
  an uncompressed `.tar` with identical entry order and metadata; the
  manifest contract is unchanged either way.

## 4. Reciprocal obligations covered

- **ffmpeg** (LGPL-2.1-or-later, `ship_runtime_pack`): dynamically linkable
  build; the installer carries the exact configure line plus the
  corresponding source generated here. Notice:
  `third_party/notices/` (kind: binary template, `third_party/README.md` §3.2).
- **llama-cpp**, **whisper-cpp** (MIT): notices travel with the pack;
  corresponding-source archives are generated by the same tool if binaries
  ship, since the contract applies to every binary-runtime row.
- **silero-vad**: model weights (not a binary build); governed by the model
  entry kind, not this archive layout. Its exact byte SHA-256 is still
  pending (pending_not_materialized in `imports/v2/heardright-assets.json`).

## 5. Pinned source snapshots

Per the interface freeze, `runtime/source/` holds the pinned llama.cpp,
whisper.cpp, Silero VAD, and FFmpeg source snapshots (corpus revisions in
`imports/v2/source-corpus.json`). Snapshot materialization and the archive
bytes themselves are produced by later pack-builder tasks; until then this
directory contains only this README and the speech-pack placeholder.
